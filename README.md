# AMDB — مرکز گزارش و پیگیری پروژه

داشبورد جامع پروژه «بانک اطلاعاتی فیلم افغانستان» (Afghanistan Movie Database).

- داشبورد آنلاین: https://armanaria111.github.io/amdb-report/
- مخزن گزارش: https://github.com/armanaria111/amdb-report
- دامنه محصول: https://amdb.af
- مسیر کد اصلی روی سیستم توسعه: `C:\laragon\www\amdb`
- فناوری ثبت‌شده: Laravel 13.39.0، PHP 8.5.12، MySQL
- نام دیتابیس ثبت‌شده: `amdbl`
- این مخزن صرفاً برای گزارش و پیگیری است و نباید کد اصلی محصول را تغییر دهد.

## خلاصه ممیزی دیتابیس

طبق ممیزی گفتگو در ۱ نوامبر ۲۰۲۶:
- ۴۲ جدول
- ۲۵ مدل Eloquent
- ۶۶ رابطه مدل‌ها
- ۲۷ route
- ۱۰ migration در وضعیت `Ran`
- صفر خطای فنی در ممیزی گزارش‌شده

گروه‌های migration ثبت‌شده: زیرساخت users/cache/jobs، professional_system، content_catalog، languages، RBAC، artist_profiles، افزودن artist_id به title_credits و translation.

نام‌های جدول ثبت‌شده در گفتگو شامل users، cache، jobs، professions، professional_requests، user_professions، professional_request_profession، content_types، titles، genres، title_genre، countries، languages، translations و title_credits است. این فهرست کامل ۴۲ جدول نیست؛ داشبورد این محدودیت را شفاف نشان می‌دهد.

## معماری و تصمیم‌های محصول

- زبان‌ها: انگلیسی `en`، دری `fa-AF`، پشتو `ps`.
- جهت دری و پشتو RTL است؛ برای هر زبان باید فونت مناسب جداگانه انتخاب شود.
- پنل‌ها: مدیریت، کاربر عادی، هنرمند/عوامل فیلم.
- کاربر عادی درخواست تأیید حرفه‌ای می‌فرستد؛ مدیر بررسی می‌کند و پس از تأیید، دسترسی هنرمند فعال می‌شود.
- هر حساب فقط یک پروفایل هنرمند دارد؛ هر پروفایل می‌تواند چند حرفه هم‌زمان داشته باشد.
- شناسه‌های پایدار: هنرمند `ar0000123`، اثر `am0000123`، شرکت `co0000123`.
- حفظ داده‌های فعلی الزامی است؛ از `migrate:fresh`، `db:wipe` یا حذف مخرب داده‌ها استفاده نشود.

## آخرین ممیزی سورس اصلی — ۱۷ نوامبر ۲۰۲۶

مخزن کد اصلی: https://github.com/armanaria111/amdb-laravel2  
مخزن گزارش: https://github.com/armanaria111/amdb-report

ممیزی فقط‌خواندنی در commit `a56e92080a227b9e4c531c9edf2e55a02e6946ab` انجام شد. ساختار بررسی‌شده شامل ۴۶۰ ورودی درخت، ۲۲ Migration، ۳۴ مدل PHP، ۳۷ فایل Blade، ۷۳ خط Route در web.php و ۷۱ فراخوانی نام‌گذاری Route بود. این آمار از مخزن GitHub است و به معنی اجرای برنامه یا بررسی دیتابیس زنده نیست.

قابلیت‌های تأییدشده در سورس: پنل‌های کاربر/هنرمند/مدیریت، RBAC، گردش‌کار عمدتاً کامل درخواست حرفه‌ای، کاتالوگ، جستجو، ترجمه سه‌زبانه، تنظیمات سایت و واردسازی هنرمندان WordPress.

موارد مهم باز:
- **ریسک امنیتی بالا:** مسیر `updateRoles` مانع کافی برای اختصاص نقش `admin` به کاربر غیرمدیر نشان نداد؛ پیش از انتشار عمومی اصلاح و تست شود.
- گردش‌کار Claim ناقص است؛ تأیید غیرفعال و مسیر عمومی ارسال در بررسی پیدا نشد.
- moderation نقدها ناقص است؛ نقدهای pending ممکن است بدون مسیر تأیید مدیریتی باقی بمانند.
- کنترل اشتراک فعال برای نمایش عمومی اطلاعات هنرمند تأیید نشد.
- public_id در مسیرهای هنرمند و جستجوی زنده یکپارچه نشده است.
- رفتار نقش artist پس از قطع اتصال پروفایل نیازمند تصمیم محصول است.

مرحله سوم ممیزی Migrationها، کلیدهای خارجی، قیود یکتا و روابط Eloquent برای جلسه بعدی باقی مانده است. جزئیات کامل در `project-status.json` ثبت شده است.

## ساختار داشبورد## ساختار داشبورد

- `index.html`: رابط جامع داشبورد
- `project-status.json`: داده‌های وضعیت، دیتابیس، قابلیت‌ها، نقشه راه و تاریخچه
- `assets/script.js`: رندر پویا، فیلتر قابلیت‌ها و بارگذاری JSON
- `assets/style.css`: طراحی واکنش‌گرا و تیره
- `CHANGELOG.md`: تاریخچه به‌روزرسانی گزارش

## نحوه به‌روزرسانی

اطلاعات تأییدشده گفتگوهای AMDB در `project-status.json` ثبت و داشبورد با هر بار بارگذاری/تازه‌سازی JSON را دریافت می‌کند. همگام‌سازی خودکار با تمام گفتگوها فعال نیست؛ هنگام دسترسی به اطلاعات گفتگوی مرتبط، گزارش باید به‌روزرسانی شود.

وضعیت «گزارش‌شده انجام‌شده» به معنی تأیید مستقل کد در لحظه نیست. اعداد ممیزی مربوط به تاریخ ثبت‌شده‌اند و درصد پیشرفت کلی تا ممیزی مستقیم کد اصلی محاسبه نمی‌شود.
