# راهنمای عملیاتی انتقال مدارک حرفه‌ای به فضای خصوصی — 2026-11-18

این راهنما برای محیط محلی Windows/Laragon پروژه AMDB است. **هیچ‌یک از مراحل زیر در این گفتگو اجرا نشده‌اند.** تا وقتی backup و بررسی dry-run کامل نشده، گزینه --apply را اجرا نکنید.

## وضعیت کد در main
- مدارک جدید درخواست هنرمندی روی دیسک private/local ذخیره می‌شوند.
- مدارک جدید درخواست عوامل/credit نیز روی دیسک private/local ذخیره می‌شوند.
- دانلود هر دو نوع مدرک از Route محافظت‌شده مدیریتی انجام می‌شود.
- فرمان انتقال legacy evidence برای فایل‌های قدیمی درخواست حرفه‌ای در main موجود است.
- فرمان retry-safe است: اگر مسیر DB قبلاً private شده باشد اما نسخه public به هر دلیل حذف نشده باشد، اجرای دوباره می‌تواند نسخه public قدیمی را پیدا و پاک کند.
- dry-run فایل‌های already-private را جدا از فایل‌های نیازمند انتقال گزارش می‌کند.

## مرحله ۱ — تنظیم مدیر ارشد
در فایل .env ریشه پروژه، مقدار AMDB_SUPER_ADMIN_EMAIL را دقیقاً روی ایمیل حساب مدیر ارشد قرار دهید؛ حساب باید قبلاً از طریق ایمیل تأیید شده باشد.

~~~dotenv
AMDB_SUPER_ADMIN_EMAIL=verified-admin-email@example.com
~~~

از آدرس نمونه بالا استفاده نکنید؛ آن را با ایمیل واقعی و تأییدشده حساب مدیر ارشد جایگزین کنید. بعد از تغییر تنظیمات، در صورت فعال بودن config cache، آن را پاک/بازسازی کنید.

## مرحله ۲ — پشتیبان‌گیری دیتابیس
نام دیتابیس ثبت‌شده پروژه amdbl است. از phpMyAdmin در Laragon یک Export کامل SQL تهیه کنید یا در صورت در دسترس بودن mysqldump از دستور زیر با نام کاربری واقعی موجود در .env استفاده کنید:

~~~powershell
mysqldump -h 127.0.0.1 -P 3306 -u YOUR_DB_USERNAME -p amdbl > .\backup-amdbl-before-private-evidence.sql
~~~

فایل پشتیبان را خارج از پوشه public سایت نگه دارید و بازشدن/اندازه غیرصفر آن را بررسی کنید.

## مرحله ۳ — پشتیبان‌گیری فایل‌های عمومی
از ریشه پروژه اجرا کنید:

~~~powershell
Compress-Archive -Path .\storage\app\public\* -DestinationPath .\backup-storage-public-before-private-evidence.zip -Force
~~~

فایل ZIP را خارج از مسیر قابل دسترسی وب نگه دارید. اگر فایل‌های عمومی دیگری هم دارید، این backup باید همه آن‌ها را پوشش دهد؛ فرمان انتقال فقط پوشه مدارک حرفه‌ای را هدف می‌گیرد، اما backup کامل برای بازگشت امن لازم است.

## مرحله ۴ — اجرای dry-run
از ریشه پروژه:

~~~powershell
php artisan amdb:secure-professional-evidence
~~~

این حالت فایل‌ها را جابه‌جا یا حذف نمی‌کند و دیتابیس را تغییر نمی‌دهد. خروجی را بررسی کنید:
- Would copy public file...: فایل قدیمی روی public است و در صورت apply کپی می‌شود.
- Would set private evidence path...: مسیر رکورد باید به فایل private تغییر کند.
- Would remove legacy public copy...: پس از ثبت مسیر private، نسخه عمومی قدیمی حذف خواهد شد.
- already private: فایل از قبل روی local/private قرار دارد و نسخه public قدیمی برای حذف پیدا نشده است.
- issues: 0: هیچ مسیر/فایل مفقود یا خطای خواندن/نوشتن شناسایی نشده است.

اگر هر موردی با issues بیشتر از صفر گزارش شد، **متوقف شوید** و قبل از apply، مسیرها و فایل‌های همان request را بررسی کنید.

## مرحله ۵ — اجرای انتقال واقعی
فقط پس از backup موفق و بررسی کامل dry-run:

~~~powershell
php artisan amdb:secure-professional-evidence --apply
~~~

فرمان ابتدا نسخه private را آماده می‌کند، مسیر دیتابیس را در تراکنش به‌روزرسانی می‌کند و سپس نسخه public قدیمی را حذف می‌کند. اگر حذف public شکست بخورد، اجرای دوباره فرمان می‌تواند آن نسخه باقی‌مانده را پاک کند.

## مرحله ۶ — راستی‌آزمایی پس از انتقال
دوباره dry-run را اجرا کنید:

~~~powershell
php artisan amdb:secure-professional-evidence
~~~

برای رکوردهای منتقل‌شده باید پیام already private دیده شود و نباید برای آن‌ها پیام Would copy یا Would remove باقی مانده باشد. issues باید صفر باشد. سپس پوشه storage/app/public/professional-evidence را بررسی کنید؛ اگر هنوز فایل عمومی وجود دارد، آن را دستی حذف نکنید تا ابتدا مشخص شود به کدام درخواست تعلق دارد.

## نکات مهم
- این فرمان فقط legacy evidence مربوط به professional_requests را منتقل می‌کند؛ مدارک credit جدید از ابتدا private ذخیره می‌شوند و مسیر جداگانه دارند.
- اجرای php artisan migrate برای Migration کاتالوگ شرکت‌ها یک کار جداگانه است و در این راهنما انجام نمی‌شود.
- تست‌های PHPUnit هنوز اجرا نشده‌اند؛ طبق برنامه پروژه باید پس از تکمیل همه تغییرات، یک‌بار در مرحله نهایی اجرا شوند.
- هیچ‌یک از دستورات این سند در این گفتگو اجرا نشده و دیتابیس محلی amdbl و فایل‌های محلی کاربر تغییر نکرده‌اند.
